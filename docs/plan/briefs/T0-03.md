## The trap
Treating execution state and work status as one status, or inferring liveness from work status. run_3 is Finished + Waiting for review: it shows a finish time and frozen elapsed, and must never land in the live group. run_4 is Running + Blocked + stale: it's still running, shown stale, and its work status stays Blocked. A combined "status" column or sort key collapses these and breaks every count downstream, including T0-05, which inherits your grid unchanged. Put sort, filter and grouping logic as pure functions in src/domain/runs/ with property tests (for example: no ended run is ever ordered into the live group; a stale run never satisfies the "live" activity filter; filtering then clearing restores the original set).
