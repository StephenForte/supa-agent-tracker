# T0-04 — Agent next steps and private notes

Two surfaces that must never blur together. Agent next steps are agent-authored instructions the user checks off. Private notes are the user's own free-form text, which agents can never see. The PRD treats the separation as a security boundary in Phase 1; in Phase 0 you make it visible and structurally honest.

## Line of work
Branch t0-04-steps-notes from the current tip of main. PR title: "T0-04: Agent next steps and private notes". Identifiers are pre-assigned; if one looks wrong, stop and ask rather than pick another.

## Outcomes
You fill the bodies of four slot components whose props are final ({ projectId }). T0-02 renders the two previews on project cards, and T0-03 renders the two panels on project detail, both in parallel with you. Do not edit their pages.
1. NextStepsPanel (src/features/next-steps/NextStepsPanel.tsx): ordered open steps (by position), each with instruction text (read-only; safe formatting only, so render text, not raw HTML), source agent name and a link to its source run (/projects/:projectId?run=<sourceRunId>), last update time, and a done checkbox/toggle that calls setNextStepDone with the step's revision. Completed steps are shown in their own section with who completed them and when, and can be reopened. The waiting note shows with its source and time. Conflict result → re-read, keep the user's intent visible, explain that the step changed and let them retry; never silently drop or force a write.
2. A clearly labelled demo-only "Simulate agent update" control inside the panel showing two scenarios through simulateAgentStepUpdate: (a) the source run rewrites a step's instruction with the correct revision → the text changes and the user's completion state is unchanged; (b) an update with a stale revision → a conflict result, with an explanation that the agent must re-read and reconcile and that nothing was overwritten. Instruction text is never user-editable.
3. NextStepsPreview: first unfinished step (nextStepSummary), remaining count, waiting note, source agent and update time; a clear "No open steps" state.
4. PrivateNotePanel: textarea editor reading and writing only through usePrivateNotes / PrivateNotesSource, with an explicit Save, visible saved state ("Saved <time>", "Unsaved changes", "Saving…"), and a conflict result that keeps the user's draft, shows the current saved text, and lets them choose. Copy states plainly: only you can see this, agents never receive it, and in this demo it is browser-only, with server enforcement arriving in Phase 1.
5. PrivateNotePreview: short truncated preview (or a quiet "No private note") for the card.

## The trap
Letting the two surfaces share a data path. If a next-steps component reads private notes, or a note ends up in anything built from TrackerDataSource, the Phase 1 boundary has a hole designed into it. Next-steps components import only useTrackerData; note components import only usePrivateNotes. Add a test that renders NextStepsPanel and NextStepsPreview with a PrivateNotesSource whose methods throw, and asserts they render normally and never call it. Add the converse for the note components with a TrackerDataSource whose methods throw.

Second trap: completion depending on the agent being alive. step_3's source run (run_5) Failed. The user must still be able to complete and reopen it. Closing a run (T0-03) never completes or removes steps.

## Must hold
- Checking or reopening a step updates the preview and panel together (same source, no local copies).
- A user completion survives a simulated agent instruction update.
- Reset demo restores seeded steps and notes; drafts don't leak across projects.
