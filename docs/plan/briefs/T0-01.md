## Step 0 — Dropbox guard (do this before npm install)
This repo lives inside Dropbox (operator's choice). Dropbox syncing node_modules/ and dist/
while you install and build causes conflicted copies and slow, corrupted trees. Before the
first install:
    mkdir -p node_modules dist
    xattr -w com.dropbox.ignored 1 node_modules dist
    xattr -w 'com.apple.fileprovider.ignore#P' 1 node_modules dist
    xattr -l node_modules dist
Which attribute Dropbox honours on this File Provider path is unverified; setting both is
harmless. Report the xattr -l output in RESIDUAL GAPS. Also add to .gitignore:
node_modules, dist, .DS_Store, *.local, and the pattern "* (conflicted copy*" .

## The trap
Getting the contracts subtly wrong in ways the placeholders don't exercise. Four workers will
code against these interfaces in parallel and the data layer is frozen after merge (PLAN.md):
a missing field or mutation surfaces as four workers each inventing a local workaround, and the
fix becomes a follow-up task plus four rebases. Before handing back, walk every screen in PRD
"Screens and interactions" and T0-02…T0-06 acceptance criteria and confirm each displayed or
mutated value is obtainable through TrackerDataSource / PrivateNotesSource. List that walk-through
in RESIDUAL GAPS as "contract coverage: checked against T0-02…06".

Second trap: building a pleasing screenshot prototype. Derived numbers computed inline in
components (counts, elapsed, stale) will diverge across Projects, Project detail and All agents.
Every derived value comes from src/domain/.
