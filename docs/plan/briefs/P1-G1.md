## The traps
1. **Merging provisions money.** With Blueprint auto-sync, render.yaml on main can create the paid web service and database immediately (D-030). The PR is a draft, its body starts with "DO NOT MERGE — cost gate (D-030): merging provisions paid Render resources", and nothing in this task merges or asks anyone to merge.
2. **`trustProxy: true`.** That trusts every hop, so `request.ip` becomes the client-controlled leftmost X-Forwarded-For value. The per-IP sign-in limit would then be bypassable by rotating a fake header. Consequence: unlimited password guessing. Use a hop count and test the spoof.
3. **A public database.** Leaving `ipAllowList` unset can default to open access in some Render setups. Set it empty explicitly, and say so in deploy-phase1.md.
4. **Breaking the static demo.** Any change to the static service block, or to the root build without env vars, changes the public site on merge. Diff the static block against main: it must be byte-identical.
5. **Secrets in files or output.** No token, password, API key or generated secret in render.yaml, docs, the PR, logs or load-script output.
6. **Touching the operator's other databases.** Only your own `supa_test_*` scratch databases.
